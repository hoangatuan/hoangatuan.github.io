## Introduction

In this article, we will explore how to integrate XcodebuildMCP into your iOS project to improve the AI-powered development experience.

## XcodebuildMCP

### What is XcodebuildMCP?

XcodebuildMCP is an MCP server that gives AI agents full control over Xcode: building, testing, debugging, UI automation, and more.

### Why XcodebuildMCP?

As discussed in the previous article, [Leverage AI in iOS development](./dont-blindly-trust-your-agent.mdx), an AI agent's goal is to provide an answer, which leads it to make assumptions and act overconfidently at the same time. Because of that, we spend a lot of time verifying and retrying.
Especially with the Xcodebuild process:

- Missing context: Agents don't know how to find the simulator, schemes, targets, and so on, which leads them to make assumptions.
- Long feedback loop: Xcodebuild is a time-consuming process, even with incremental builds.
- Context consumption: Xcodebuild logs are verbose and painful to read.
- Missing abilities: Agents don't know how to manage simulators, capture logs, take screenshots, and more.

### Integration

There are several ways to integrate the MCP. In my experience, the best approach is to integrate XcodebuildMCP at the project level and commit all configuration files. This way, the team shares the same configuration and workflow.

1. Create a project-level `.mcp.json` file in your iOS project:

```json
{
  "mcpServers": {
    "XcodebuildMCP": {
      "command": "npx",
      "args": ["-y", "xcodebuildmcp@latest", "mcp"]
    }
  }
}
```

2. Create a `.xcodebuildmcp/config.yaml` file:

```yaml
schemaVersion: 1
sessionDefaults:
  projectPath: "./MyApp.xcodeproj"
  scheme: "MyApp"
  simulatorName: "iPhone 17 Pro"
  configuration: "Debug"
enabledWorkflows:
  - simulator
  - ui-automation
```

## Example Use Cases

The goal when using agents is to create a [closed-loop](https://antran.app/blogs/2026/clossed_ai_loop/), so the AI can implement, verify its own results, and loop until the requirement is met. It's similar to what Claude `/goals` does.

**1. Fix build errors autonomously**

With XcodebuildMCP, the agent runs a build, reads the structured diagnostics, makes edits, rebuilds, and repeats until the project compiles, without human intervention.

**2. UI automation with XcodebuildMCP**

XcodebuildMCP can automate UI actions such as swiping, tapping, and scrolling. Best of all, you can describe those actions in natural language.
With this, we can close the E2E loop: `Requirement → Implementation → Build → UI verification` until the requirement is met.

**Example**

Here is the requirement I gave to my agent in an example chat app:

```
Let's implement a feature that allows users to recall their messages. On long press, show a popup asking whether they want to recall; they tap YES or NO.
After you implement it, run UI automation to verify it works. The recalled message should disappear.
Loop until the requirement is met.
```
